# 主问答反馈、旧结果复查与一次补搜

沿用上一轮的三道调优题和三道开发保护题，逐题冻结候选顺序、筛选 Agent 首次选中的四块及回答设置。为测量反馈本身的效果，三组从相同的四块起步。主模型与原回答使用同一个专用模型，反馈请求只给题目和原先实际完整送达的原文，由主模型指出还缺哪些可查的事实。叙述题与数值题使用同一流程。

| 实验组 | 允许做什么 |
| --- | --- |
| 无反馈 | 用上一轮首次筛选的四块重新回答。重新发送前，逐题核对请求与上一轮完全一致。 |
| 只翻旧结果 | 有缺项时，筛选 Agent 先审阅本题第一次搜索的全部二十块，可重选四块。认定某项已补到时，必须给出所选块中的逐字引文。 |
| 旧池后可补搜一次 | 复用上一组的决定，若有尚未补齐的具体事实，可执行一次定向混合检索。按原公司及截止日限定报告，剔除重复块，筛选 Agent 在旧块和新增块中合计选四块。 |

这里的旧结果是本次真实初搜的整批二十块。没有把往日其他实验的搜索历史或研究摘要混进来。引文能逐字匹配，只证明这段话存在。正确性与引用支持另由隔离裁判判断。请求超时、编号或引文无效、检索失败时沿用最近一次有效四块，记录对应的失败阶段。新查询、候选原文、反馈及模型回答均只保存在私有目录。

同一道题三组均重新回答、评分。一次反馈和一次旧池筛选由后两组共享，成本分析只记一次。调优及保护样本分别报告，复跑使用相同四块，按实际请求指纹验证。真实回答与预算核验均使用原生最终节点。

```bash
python -m timeguard.four_feedback "$SOURCE" "$POOLS" "$INITIAL" "$OUT"
python -m timeguard.four_feedback "$SOURCE" "$POOLS" "$INITIAL" "$REPEAT" --repeat "$OUT" --ids "$QUESTION_ID"
python -m unittest discover -s tests -q
```
