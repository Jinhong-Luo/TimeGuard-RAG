# R1 财报证据实验

R1 使用 R0 冻结的 84 份财报、原生 Elasticsearch 混合检索、本地 BGE 和相同的 low 生成模型。原始 150 题、旧裁判及生产中的 RAGFlow 网页服务保持独立。新原生问答在项目容器的独立进程调用固定版 `async_chat`。普通单题和开发集批处理共用同一套逻辑。

## 引用校准

原生提示块按已展示块数从 1 编号，后处理按候选列表的零基位置解析。R1 按原生候选位置从 0 编号，空块保留位置但不显示。模型调用前逐个核对渲染后的整块是否仍在最终系统提示中。裁判要求位置、文档 ID、稳定块 ID 和正文摘要一致。被预算排除、部分裁剪、正文缺失或编号越界的标记进入不完整状态。记录包含模型原始输出、原生补引用分支、最终答案和引用候选。

旧 150 题中，旧规则判为映射完整的有 107 题，42 题不完整，1 题无引用。抽查包包含 25 题，覆盖全部 5 道旧裁判未知题，并从正确、错误及越界组合中抽样。旧会话保存的候选和最终答案无法确定每个标记的来源，抽查表同时列出两种解释。例如，强生地区销售题的 `[ID:6]` 在旧规则下越界，但第六块确实包含美国增长 3.0%、国际下降 0.6% 的原文。亚马逊收入增长题的 `[ID:2]` 按旧规则能映射到第三块，但包含季度数值的资料实际位于第二块。

在项目根目录执行以下命令。打开输出目录中的“人工复核.html”，填写复核人及判断后导出，可保留部分已核题目的记录。公开汇总只记录人数和计数。

```bash
python3 -m timeguard.citation_audit runs/all-selected/low --output runs/我的引用抽查
python3 -m timeguard.review_form runs/我的引用抽查
```

## 检索与时间

A 使用原检索，B 根据题目中的公司名或别名限定文档。C 在相同候选中按正文的期间线索重新排序，报告年份仅用于同分排序。D 在候选为空或缺少指定期间时，在同一允许范围内扩大候选池后再返回前六块。C 只有顺序可能改变，评估它时应查看前一位命中和回答效果。财报可能在较晚年份重复披露历史数字，普通财年查询允许使用这些报告。

历史问题支持明确的截止日。日期台账按申报登记号或实际 PDF 的 SHA-256 绑定到已核实的公开来源。范围按**截至指定日期当日结束**解释。发布日期缺失的文档不进入带截止日的检索。百事信贷协议发生于 2023-05-26，相关 8-K 于 2023-05-30 提交，两天在系统中对应不同的可见文档范围。[SEC 申报记录](https://www.sec.gov/Archives/edgar/data/77476/000110465923066134/0001104659-23-066134-index.htm)

首轮对照使用提交 `cde66d0`。发布版本补充 JnJ、JPM、季度、多年区间、文字日期和带来源的披露日期，并单独进行复验。输入来自问题、PDF 和文档台账。金标留在评测端。问答的诊断检索记录来自本次原生检索，模型实收范围以本题引用轨迹为准。

```bash
# 在已经配置 RAGFlow 与模型桥凭证的项目服务器执行，输出目录须使用新名称。
python3 -m timeguard.retrieval_experiment --split tune --output runs/我的调优矩阵
python3 -m timeguard.r1_dev --arm D --finance-prompt --output runs/我的开发集
python3 -m timeguard.filing_trial --output runs/我的披露日检查
python3 -m timeguard.ask 'What were 3M net sales in FY2018?' --as-of 2019-02-07 --output runs/我的单题
```

原生问答驱动复用 R0 的项目专用容器、知识库及 low 对话配置。每次创建独立的运行目录，记录源码、配置、索引和模型调用审计。独立进程内的提示与引用修正不改变原网页聊天的行为。模型批次应独占本项目桥审计窗口。服务器已有的私有凭证加载器可以用 `python3 .cache/run_module.py timeguard.模块名` 启动对应命令。代理转发中断时，可在运行本机代理的 Windows 终端执行 `powershell -File scripts/open_model_proxy.ps1`。

## 表格、重排与上限诊断

表格试验从 3M 2018 年报原生索引取出全部可用表格，使用原 PDF 和相同 Embedding 新建两套知识库。对照组整表检索，行组试验复用原表题和表头，每组最多六行数据。多表或跨行单元格保留完整原表。返回小块后按稳定 ID 扩展为原始父表，证据页按原始位置核对。两组只覆盖同一份报告的同一批表格，输入问题按公开公司和期间筛选。

专用重排使用固定版本的 `cross-encoder/ms-marco-MiniLM-L6-v2` 和项目内网 CPU TEI 服务。原生提供商以 `truncate=false` 发送超长财报片段，产生了长度拒绝。独立对照冻结每题已有的 24 个原生候选，按模型分词器裁剪**评分输入**，再返回六个完整原文块。标准证据上限试验把金标证据交给模型，保留同一 low 生成模型和独立 medium 裁判，其结果单独报告。

```bash
python3 -m timeguard.table_trial --output runs/我的表格试验
python3 -m timeguard.reranker
python3 -m timeguard.retrieval_experiment --arm B --native-pool 24 --output runs/我的原生重排对照
python3 -m timeguard.retrieval_experiment --arm B --native-pool 24 --reranker 'cross-encoder/ms-marco-MiniLM-L6-v2@timeguard_r1_ce_tokenizer@HuggingFace' --output runs/我的原生重排
python3 -m timeguard.rerank_trial --source runs/我的调优矩阵 --output runs/我的固定池重排
python3 -m timeguard.oracle --output runs/我的标准证据诊断
python3 -m timeguard.oracle --table-trial runs/我的表格试验 --table-arm rows --output runs/我的行组回答诊断
```

## 财报计算接口

应用使用 Python 3.11 及以上版本。在项目单独的虚拟环境安装依赖，并在已配置服务凭证的终端启动。

```bash
python -m pip install -r requirements-app.txt
python -m uvicorn timeguard.app:create_app --factory --host 127.0.0.1 --port 19102
```

`POST /turn` 接收 UUID 格式的 `session_id`、`request_id`、最近收到的 `revision` 和问题，可另传 ISO 格式的 `as_of`。首次请求版本为 0。相同请求重放返回原结果。续问沿用会话 ID 和新的请求 ID。SQLite 保存历史、回答、引用和用量。用 `GET /metrics` 核对在途量、容量拒绝、上游错误和已返回的 token。服务面向单用户回环部署。

LangGraph 依次执行原生检索、工具调用解析、稳定证据回读和 Decimal 运算。模型通过桥返回 `tool_calls`，应用校验函数名及参数，并执行计算或缺参追问。响应保存 `tool_call` 的编号和名称，可从 `facts` 核对每个操作数。工具支持同比增长率、同期间利润率和比率，检查数值原句、年份、季度、币种、金额单位及分母。金额括号按负数读取。未明确币种的两个金额仅允许来自同一个带货币符号的财务表。指标行和多列表头的业务含义仍依赖模型选取。服务有限时和容量上限，只对只读检索的连接或读超时做有限重试。连续上游异常后暂缓请求，冷却后通过单个请求探测恢复。

```bash
python -m timeguard.app_trial --calculate --output runs/我的接口实测
```
