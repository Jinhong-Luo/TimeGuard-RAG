# FinanceBench 配对评测

同一题分别交给原生参照 A0 和增强版 A1。两组共享可见财报范围和 8,000 token 最终证据预算，各自从空会话检索作答。[冻结排期](../configs/financebench-schedule.json) 给出每题的运行顺序和分组。作答端只拿题干及题目所带的截止日。标准答案与标注证据由独立评分端读取。

## 检查排期

先按[数据准备与入库](部署与入库.md)生成 `data/financebench/queries.jsonl`。计划模式只读取查询集和排期。运行器要求同时提供 `--setup` 和 `--output` 参数，计划模式不会打开它们。

~~~bash
python3 -m timeguard.evals.financebench_paired --stage plan \
  --schedule configs/financebench-schedule.json \
  --setup runs/setup.json --output runs/financebench-plan
~~~

## 运行与评分

在准备好索引的环境提供对应的原生对话配置、二十项程序检查结果和模型入口。程序检查的参数可用 `python3 -m timeguard.evals.financebench_checks --help` 查看。原生对话配置需与冻结索引的 `dataset_id` 一致。以下示例使用官方 OpenAI API，密钥来自运行环境或服务器私有文件。使用 Codex 登录桥时选择 `--model-provider codex`。

~~~bash
python3 -m timeguard.evals.financebench_paired --stage pilot \
  --model-provider openai --schedule configs/financebench-schedule.json \
  --setup "$TIMEGUARD_SETUP" --program-report "$TIMEGUARD_CHECKS" \
  --output runs/financebench-new
~~~

首批为六对开发题。核对后，同一冻结配置可把 `--stage` 改为 `all` 运行全量，先前成功位置计入全量。换代码、模型或索引时使用新的输出目录。调优、开发、跨公司保留组分别汇总。请求失败、零召回和未知判断保留在原分母里。评分单列答案正确、实际引用支持及二者同时满足的题数，模型裁判和人工复核分别标记。

## 查找材料

- `runs/<批次>/summary.json` 是该批汇总。逐次尝试和逐题裁判在同批次目录。
- 本地归档 `reports/` 存放历史汇总，`reports/docs/` 存放逐轮实验报告，`reports/FinanceBench/` 存放正式配对汇总。新克隆按需复制对应归档；早期复验脚本会按原来的 `reports/<文件名>` 查找冻结输入。
- 历史实验按当时的提交复现；[逐题回放说明](../web/trace/README.md)给出如何从真实记录构建离线页面。
