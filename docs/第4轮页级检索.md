# 第 4 轮　允许报告内的页级检索和定向补查

先用问题确认公司和适用披露截止日，与原生会话文档范围取交集。按报告分页读取 RAGFlow 索引原块，组合每页的指标、报表或章节词、期间及正文词，按页内最相关块与该页覆盖的查询词加权排序。取前四页，每页最多三块。补查组在同一已缓存的报告内，当问题中的期间和指标缺少共同出现的段落、趋势缺少对比期间或明确概念缺失时，最多再搜两页。重新编号后总量仍不超过 12 块。日期取自已验证的申报目录，有明确截止日而该报告缺少核验日期时排除。首次使用一个报告时需要分页读取原块，后续题在同批内复用。

### 三组对照

三道预定调优题先实际生成、评分，再跑八道开发回归题（六道上次漏页，另两道上次判对）。各题三组保持同一问题、研究摘要、上游代码、索引、回答模型和 8,000 token 预算。原组保留原版最终选块，第二组替换成页内原块，第三组在第二组基础上允许补查。三次最终回答独立生成，各自调用相同裁判。页级检索增加了新的材料，和第 1 轮只在固定候选池内排序的实验不同。此处的页级真回答是冻结研究状态后的末端对照。

### 历史漏页与操作数

六道历史漏页题共需要七个标准题页组合。这次原生检索在全部轮次命中其中四题各一页。页级检索命中其中一题一页，与原生重新找回的页重合；该题仍错。补查新增命中 0，新增判对 0。另两道历史正确题的原生各轮检索都命中标准页，页级均未命中。三组均判对其中一题。为获得同批原生快照，另跑了八题真实端到端生成，共 125 次调用、0 失败、2,618,378 token、634.25 秒，采集后裁判 8 次、0 失败、74,849 token、51.33 秒。详见[逐题归因](../reports/round4-historical.json)。

对调优集中的跨期固定资产周转率题，按标准页单独列出三个应有操作数，以实收完整渲染块核查。原版能找到 3/3 个字面金额，页级和补查均为 0/3。按现有严格的行名、年份与单位规则，本次所有方案通过的操作数均为 0/3。严格规则对摘录和表格格式有局限，不能由金额出现直接断定期间正确。核验清单只供离线评测，详见[逐轮操作数核验](../reports/round4-operands.json)。

### 复现

从真实原生快照运行以下命令。页检索需要项目只读 API 和现有私有运行配置。私有批次在 `runs/finance-round4-20261115-a`，回归采集来源在 `runs/finance-round4-snapshots-20261115-a`。

```bash
python -m timeguard.paired_trial "$SOURCE" "$NEW_RUN" --arms original page supplement
python -m timeguard.paired_report "$NEW_RUN" data/financebench/gold.jsonl "$NEW_RUN/页级.json" original page
python -m timeguard.paired_report "$NEW_RUN" data/financebench/gold.jsonl "$NEW_RUN/补查.json" page supplement
python -m timeguard.page_report runs/evidence-layers-20261111-d/pages.json "$SOURCE" "$NEW_RUN" data/financebench/gold.jsonl "$NEW_RUN/历史归因.json"
```
