# 部署与入库

以下命令在 Linux 仓库根目录执行。已有共享部署可以直接使用其服务和项目目录。在新环境准备独立部署时，需要 Git、Docker Engine 和支持 `include` 的 Docker Compose v2。

~~~bash
python3 -m timeguard.operations.bootstrap --prepare-compose --local-embedding
docker compose -p timeguard_ljh -f deploy/compose.generated.json config --quiet
docker compose -p timeguard_ljh -f deploy/compose.generated.json up -d
python3 -m timeguard.indexing.data --pdfs
~~~

生成的 Compose 复用上游服务。运行配置在 `deploy/`，数据与模型缓存在 `data/`。在共享服务器选择本项目的端口和 Compose 项目名。GPU 解析使用 `deploy/` 中的解析配置和镜像锁，构建所需的 wheel 哈希与版本约束在 [deploy/locks](../deploy/locks/)。

用现有 RAGFlow 项目账户设置 `RAGFLOW_API_KEY`，并确认服务注册的嵌入模型标识。入库进度写入本地台账，可用相同配置复查。

~~~bash
python3 -m timeguard.indexing.ingest --embedding-model 'BAAI/bge-small-en-v1.5@local_tei@HuggingFace'
python3 -m timeguard.indexing.ingest --embedding-model 'BAAI/bge-small-en-v1.5@local_tei@HuggingFace' --status
~~~

[会话 API 的 Compose 配置](../deploy/compose.app.yaml) 列出服务端环境变量、会话数据库和只读挂载。应用工厂为 `timeguard.server.app:create_app`。访问现有服务器的回环服务、查询容器状态与数据位置见[服务器使用](服务器使用.md)。
