# 完整 39 道开发题的缺项补搜验证

本轮从 `f2d75e19fab9cc2a732f062263b43e7195a6273b` 继续。固定上轮的公司范围、披露截止日、原生索引、原生最终回答节点、模型、筛选提示和裁判。所有开发题按问题原文进入流程。金标只用于最后的评测。

**主指标**要求同一题的模型裁判同时给出“答案正确”和“引用有支持”。只答对、引用不足或未知，都不能计为达标。首次配对用全部 39 题。报告列出每题的两个独立判定，也单列移除曾作为保护样本的三题之后的 36 题。这是开发集验证，未包含新的保留公司。

| 对照 | 该对照回答的问题 |
| --- | --- |
| 完整流程相对无反馈 | 已有筛选 Agent 从二十块选四块，再加主模型反馈、复查旧池、必要时一次搜索和重选，合计有没有收益？ |
| 可补搜相对只翻旧池 | 两组已做完全相同的反馈与旧池复查，只给一组一次定向搜索及重选机会，这一步单独值多少？ |
| 只翻旧池相对无反馈 | 在原来的二十块内重新选择，能否改善带引用的正确答案？ |

38 题均从各自允许的财报中实际检索到二十个不同的块，首次筛选都成功。另有一道题无法从提问确定公司，三个条件都执行原项目的公司澄清规则，保留在 39 题分母。所有组使用相同的四块上限及 8,000 token 证据预算；遇到缺项，额外搜索最多一次。评测比较固定四块流程，不能把结果直接套在历史完整多轮 Agentic medium 的正确数上。

**共享相同请求。** 所有实际回答与评分均为本轮重新运行。同一题两个条件的完整模型请求、证据块指纹和实收位置全部相同，就共用本轮这一次回答与裁判。材料有任何变化，分别重新生成及评分。这样可避免在完全相同输入上因随机输出产生虚假的救回或损失。实际调用与三组各自的逻辑结果分开记录。

**每题成本。** 在全部 39 题上累计增量调用。除以“此前未达标、现在达标”的题数，得到每救回一道所多花的调用。再除以“救回减损失”，得到每净增一道的成本。分别列模型请求和原生索引请求。首搜、首次筛选和最终回答是共享的业务步骤，裁判与复验是评测开销，都不计入补搜的增量调用数。最终回答输入长度、耗时变化仍单独计量。净增量小于等于零时不计算每净增一道的成本。

在项目服务器的专用服务环境设置 SOURCE 为已有完整开发集快照，OUT 为新的私有目录。完成的步骤按题保存，恢复时在同一目录重用相同输入，失败调用留存。原始文档、候选和模型请求不进入 Git。

```bash
python -m timeguard.full_feedback "$SOURCE" "$OUT" select
python -m timeguard.full_feedback "$SOURCE" "$OUT" trial
python -m timeguard.full_feedback "$SOURCE" "$OUT" grade
python -m timeguard.full_feedback "$SOURCE" "$OUT" confirm
python -m unittest discover -s tests -q
```

38 道有公司范围的题各做一次主模型反馈，其中 20 题有缺项。旧池复查 20 次，没有改变任何题的最终请求。20 次定向索引搜索全部执行，20 次补搜后筛选中有 2 次回退，最终 11 题改变了实发材料，其中 4 题由未达标转为达标。补搜找到 13 个初搜未命中的标准题页；最终实收标准题页净增 4 个。前三道获救题的标准页均由补搜首次找回并完整送达；01912 的两个标注页均未送达，模型裁判认定其他实际引用足以支持答案。

**模型与时间成本。** 主反馈、旧池复查、补搜后筛选分别使用 306,048 / 2,349、354,803 / 1,899、608,546 / 7,392 个输入 / 输出 token。三阶段累计耗时分别为 550.0、280.9、384.7 秒；20 次索引搜索合计 7.1 秒。完整流程额外使用 1,269,397 个输入、11,640 个输出 token。另算最终回答，完整流程相对无反馈的逻辑用量合计多 5,736 个输入、460 个输出 token。均为按请求累加，实际批次并发执行。

**评测开销。** 首次全量三组共享相同消息后，实际生成 49 个模型回答，另有 1 次规则澄清，共调用裁判 50 次；回答与裁判均无失败。20 次搜索和 2 次筛选回退都保留在成本中。共同初搜 38 次、共同首次筛选 38 次、每个服务批次的连通性探测，不计入增量成本。实际与逻辑调用、逐题页数、操作数、未知判定及复验结果见[脱敏机器报告](../reports/dev39-feedback-supported.json)。

**独立重答。** 锁定四道获救题的模型请求与引用映射，重新生成 8 个不同请求的答案并重新裁判 8 次。四题全部复现相同变化：原来未达标，补搜后答案正确且引用有支持。复验未再次筛选或搜索，不重复计为新增题。共有 187 项项目回归测试通过。

保留按具体缺项定向补搜的实验配置。本次验证覆盖完整开发集，适用于同一候选选四块的流程；尚未验证将它接入线上原生多轮研究后能否得到相同净增，也未测新的未见公司。仅回看消耗了 20 次筛选而未改变最终材料，可以在后一组独立实验中验证省略该步骤的效果。
