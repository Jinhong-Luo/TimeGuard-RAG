## 是否分流

对于可识别的单年查数，先检查同一公司、期间、单位和原文行列能否给出唯一值。不足时走原生研究。对于多期或最终候选缺同期间指标的题，最多审查一次，校验返回块编号与原文，失败后回退。程序原文读取与模型生成分别计数。

首次三题端到端分流判对 2/3、引用支持且判对 2/3。第 0 轮原生端到端判对 1/3，两组错转对 1、对转错 0。03029 经 15 次索引分页与 11 次回读仍无法直接取数，随后走原生研究与一次缺项审查。02987 触发多期审查，01226 走原生，两次审查都通过。审查共用输入 25,436、输出 659 token、23.06 秒。分流全部生成阶段 40 请求、0 失败、491,150 token、322.72 秒；另有 3 次裁判、0 失败、30,565 token、16.86 秒。第 0 轮生成 35 请求、0 失败、537,473 token、302.19 秒。两批研究轨迹各自重新生成，不能据此把 token 差异归到审查。见[分流逐题记录](../reports/round6-route.json)和[原生采集](../reports/round0-snapshot.json)。

将首次唯一错转对的 03029 再次从头检索、回答、评分，原版和分流均判对且引用支持。两者各用 10 次生成请求，分别 96,708、100,655 token。分流版再次读取索引 15 次、回读 11 块，这次原生研究后没有触发审查，标准页完整送达。对照也能用同报告其他支持材料答对。没有复现净增正确，保留原生研究与回答，第二个 Agent 默认关闭。现有结果还无法确定应常规升级的题型。详见[原版复跑](../reports/round6-repeat-final.json)和[分流复跑](../reports/round6-repeat-route.json)。

## 核验口径

最终候选使用 RAGFlow v0.27.3、原生公司过滤及 Agentic medium。保留原研究循环，每题执行公司和适用披露截止日范围门控，原生筛选再与允许文档相交。无公司线索时请求澄清。生成阶段只能看到题目及允许财报；标准页、参考答案和计算操作数的事后核对只在评分端使用。

最终裁判按成功回答请求中实际完整送达的块映射引用。历史 39 道开发题里，37 题带显式编号，共有 65 个题号与编号组合。其中 58 个在旧映射与实收映射下指向不同块，5 个按实收仍无法定位，2 个一致。历史引用支持率不能直接比较。见[历史编号审计](../reports/round6-legacy-citations.json)。

项目环境通过 166 项项目测试和 21 项模型桥测试，覆盖审查超时与错误编号、补查超时后保留首批页、证据预算溢出、公司与截止日范围、熔断、幂等、恢复后成本对账。开发及保留题均没有附带具体披露截止日；截止日拦截结果来自回归测试。

## 完整开发集

39 道题逐题生成并交给模型裁判，22 对、16 错、1 未知；17/39 判对且引用支持。仅看引用，25 题获支持、8 题不支持、6 题未知。与历史 19/39 对照有 6 道错转对、3 道对转错。两批独立生成，最终配置另有明确范围门控及实收编号映射。历史同配置还有一次 20/39，本次差值不用于证明某项改动提高准确率。

总计 46 个标准题页组合。各轮检索命中 35，进入最终节点时 31，选中 26，装入 26，实收完整渲染块命中 20。完整渲染块中，能与索引原块逐字对上的标准组合为 4。其余可能是原生研究编辑或节选的材料。进入合成的 38 题全部复现选块、包和实发请求；另 1 题因未能从问题确定公司而直接要求澄清。此次入口前净减 4 个、最终选块再净减 5 个，不能把旧批次 35→24 按这个比例拆分，也没有观察到入口前损失占主导。

可由程序识别公式的 5 道题共需 19 个操作数，严格回读确认 0/19。00799 速动比率题与 00684 多期毛利率题均在检索中命中标准页，最终未完整送达，均判错。05915 固定资产周转率题判对，但引用不支持；两个标准页均未完整送达。01254 得到未知判定，显式引用映射不完整。

生成侧专用桥审计 545 次请求、2 次失败、8,706,261 token，两批计时合计 2,417.55 秒；其中首次 351.43 秒按从建清单至恢复元数据的上界计。裁判 39 次、0 失败、358,539 token、175.22 秒。首次 SSH 重置前落盘 3 题，桥已记 71 次调用；在源码、索引、题单和结果指纹核对后复用这 3 题，补跑 36 题使用 474 次调用。未落盘题目的旧请求仍计在整批桥成本内，无法分摊给单个问题。客户端逐题轨迹另记录了 5 次 HTTP 或连接失败，桥端记录的 2 次失败与客户端口径单列。断线时可能存在未完成审计的在途请求。完整结果见[开发集逐题与分阶段统计](../reports/round6-final-dev.json)。

## 跨公司保留集

冻结配置在 7 家公司的 23 道保留题上重新检索、生成、评分。11 题判对、11 题判错、1 题未知，6/23 判对且引用支持。仅看引用，8 题获支持、12 题不支持、3 题未知。此批没有同条件的另一组新回答，错转对、对转错与新增成本不适用。

29 个标准题页组合，检索命中 24，进入最终节点 15，选中 10、装入 10、完整实收 9；其中 1 个实收组合有与索引原块逐字相同的正文。22 个最终节点的三项快照回放全部一致，另 1 题缺公司线索而要求澄清。保留组入口前净减 9 个组合，多于最终选块净减的 5 个，与开发集的损失分布不同。保留集结果未用于调整参数。严格操作数检查器在这 23 题上没有识别出可以逐项核验的公式，操作数完整率无分母。

生成侧 418 次请求、0 失败、9,361,823 token、1,578.37 秒；裁判 23 次、0 失败、214,839 token、97.36 秒。两组实收与检索块通过允许报告范围核对。模型身份与推理档位分别通过专用桥审计。项目现有 150 道已标注题和 84 份索引报告都已归入三个既有集合，保留集与调优、开发没有共享公司或报告。该组过去已经运行过；全新泛化成绩还缺未参与既有运行的题目及预先封存的证据、公式和容差。见[保留集逐题与分阶段统计](../reports/round6-final-test.json)与[公司和报告隔离](../reports/round6-splits.json)。

## 复现入口

使用已有索引与专用服务，为每次运行填写新的私有目录。预算与分流小样本的裁判和回答分别计费。开发集与保留集使用独立题目清单和相同配置。原始请求、裁判理由、财报表格和认证信息只存项目私有环境。

```bash
python -m timeguard.paired_trial "$SOURCE" "$PAIR" --arms original wide
python -m timeguard.native_baseline --output "$RUN_DIR" --metadata populate
python -m timeguard.native_baseline --output "$RUN_DIR" --metadata checks
python -m timeguard.native_baseline --output "$RUN_DIR" --arm combined --candidate final --split dev
python -m timeguard.native_baseline --output "$RUN_DIR" --metadata restore
python -m timeguard.native_matrix --output "$RUN_DIR" --stage judge --run "$ARM_DIR"
python -m timeguard.final_report "$ARM_DIR" "$SUMMARY" --check-operands --old "$OLD_DEV"
```

`RUN_DIR` 需要项目专用准备步骤生成的 `setup.json`。确认 `metadata-checks.json` 通过后开始生成，异常路径也需恢复元数据。运行保留集时将分组换为 `test`，汇总省略 `--old`。未完成的生成在新目录通过 `python -m timeguard.native_recover --source "$ARM_DIR" --output "$RECOVERY"` 续跑，之后用恢复目录评分和汇总。
