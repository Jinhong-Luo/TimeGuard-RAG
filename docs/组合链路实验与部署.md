# 组合链路实验与部署

## 实验入口

固定上游为 RAGFlow v0.27.3。先按原生基线流程准备公司元数据、项目专用模型桥及含 `setup.json` 的新运行目录。每个候选从同一个公司过滤与 Agentic medium 组合出发。工作进程退出时释放钩子，不修改在线服务代码。模型实验要串行占用专用桥，才能把生成和裁判的审计窗口分开。

```bash
python -m timeguard.native_baseline --output "$RUN_DIR" --arm combined --candidate sca1 --split tune --limit 2
python -m timeguard.native_matrix --output "$RUN_DIR" --stage judge --run "$RUN_DIR/combined-sca1-smoke"
```

|候选|改变的环节|
|---|---|
|evidence|在原生最终回答图节点按照文档编号、块编号回读索引，验证正文，给进入提示的证据建立从零开始的连续编号。从裁剪后的消息检查整块是否实收。|
|concise|在最终回答阶段要求只给目标结论、必要数值、公式和逐项来源。|
|fallback|在最终节点无证据、原范围非空且未发起过检索时，限原范围补查一次。|
|temporal|对原生公司过滤结果与经核验的披露范围取交集，正文期间参与排序。缺公司时追问。|
|sca1、turn2|分别把原生复查上限改为一轮、工具会话上限改为两轮。|
|finance|用原生召回、索引回读、可见表头及 Decimal 计算核验明确的计算题。金额比率、多期同指标汇总、两期百分点差各有输入约束。|
|adaptive|单财年、明确指定 USD millions 的少量查数题先验证公司、表名、行名、列年和单位。条件不齐时进入 medium 图。|
|layers|原生组合的诊断模式。记录各次检索与整份文档读取、最终证据包及成功模型请求中的完整渲染块。回答结束后按块号回读索引，区分完整索引原文和上游处理过的摘录。|

指定已知回归题使用 `--query-ids`；用于评测选题的题号不作为模型输入。每个新方案建立独立结果目录。生成结束后再运行裁判。使用 `timeguard.agentic_results --runs ... --output ...` 汇总实际请求、已返回 token、裁判结果及证据映射。

### 三层证据对照

在已准备好公司过滤、专用模型和 `setup.json` 的同一实验环境中执行。以下变量分别指向本次运行根目录、按当前裁判规则评分的标准证据组、历史原生组合运行目录。

```bash
python -m timeguard.native_baseline --output "$RUN_DIR" --arm combined --candidate layers --split dev
python -m timeguard.native_matrix --output "$RUN_DIR" --stage judge --run "$RUN_DIR/combined-layers-dev"
python -m timeguard.layer_report --normal "$RUN_DIR/combined-layers-dev" --oracle "$ORACLE_DIR" --baseline "$BASELINE_DIR" --details "$RUN_DIR/逐题页码.json" --output "$RUN_DIR/汇总.json"
```

标准证据组使用 `timeguard.oracle` 生成的开发集回答。复用回答时，复制原 `manifest.json`、`results.jsonl`、`audit.jsonl` 到私有的新目录，然后调用相同的 `timeguard.native_matrix --stage judge` 评分。汇总时逐题重建裁判输入并核对摘要。两组使用同一生成模型和评分规则。标准证据组采用直接回答提示，原生组合组还会生成研究摘要。

逐题页码统一使用 PDF 阅读器从 1 开始的页号。候选保留每次调用的通道、图节点、轮次、报告编号和页码；同一检索可以经过多个通道，调用记录不能直接相加作为独立搜索次数。最终包同时记录待选块和经过块级预算后渲染的块。模型实收按专用桥成功请求的最后一条用户消息逐块核验。消息中的研究摘要、截断的半块、引用编号均不能单独证明某个原块已完整送达。各层未知记录单列；同题多次合成时仍输出每次证据清单，汇总保持未知。详细轨迹和原始文本留在私有运行目录。

逐题原始轨迹留在私有运行目录。图节点记录输入候选数、轮数、返回状态及异常类型。固定桥端口 18866 的异步 HTTP 调用可记录返回的请求编号和用量。失败未返回的用量保留未知。整个批次的真实请求总数以独占模型桥审计为准。候选池中的块、完整展示给模型的块以及答案实际引用的块分别记录；完整编号映射只证明可追溯。

## Linux 服务器上的应用演示

在仓库根目录准备已核验的文档目录、索引清单、RAGFlow 与模型服务。按项目既有方式将 `RAGFLOW_API_KEY` 和 `CODEX_BRIDGE_TOKEN` 注入环境，需要时设置 `CODEX_BRIDGE_BASE_URL`。下面的命令启动一个监听 127.0.0.1:19112 的单进程应用，使用独立卷保存 SQLite 会话。

```bash
docker compose -p timeguard_app_demo -f deploy/compose.app.yaml up -d --build
curl -fsS http://127.0.0.1:19112/metrics
python -m timeguard.app_trial --base-url http://127.0.0.1:19112 --output runs/app-demo-new --calculate
docker compose -p timeguard_app_demo -f deploy/compose.app.yaml down
```

部署的 FastAPI 提供财报计算、追问、会话和请求重放。原生多轮组合链路的候选通过上文评测入口运行。表格跨行跨列、期间无法对齐或操作数不齐时，计算工具会给出缺项。部署仅挂载运行必需的两份索引目录文件。单进程容量、超时、熔断及恢复验证不能外推到多租户或多副本服务。
