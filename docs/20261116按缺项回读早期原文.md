# 按缺少的财务事实回读早期搜索原文

本实验从第六轮提交 `6b2a6271f981deea088b3afae63c8712a0736e43` 继续。问题是研究过程早先搜到过一张有用的表、最终候选却没有这张表时，能否按缺项把原文重新送给回答模型。此次只增设固定快照配对入口，线上默认配置沿用第六轮。

## 怎样回读

1. 沿用原有公式和读表程序，从问题得到需要的指标及期间。逐项检查原版回答实际收到的完整块。未通过严格核验表示程序无法确认，材料里仍可能有这个数。
2. 有缺项时，遍历本题此前各次搜索的原块编号，只读最终入口里没有的块。按报告和块编号去重，检查公司、披露截止日、索引身份、文档编号及原文指纹。全程使用已有搜索结果，无额外语义检索、审查模型或标准答案。
3. 第一种规则只接受能够核准行名、年份列、金额与单位的原块。第二种还允许一张唯一匹配的合并原表作为材料。程序可识别全称后的缩写，要求同一张表有目标行、有数值、此前有含目标年份且列数相同的表头。公开记录把这类材料标为“待核原表”，其中的金额和币种仍待核实。
4. 两种装入方式均使用上游渲染器、原问题、原摘要、最多 12 块和原有的 8,000 token 证据预算。第一种要求原版实收的每一块都保住，否则整题退回原版。另一种允许原表占用原有位置，记录挤掉多少原有实收块。两种都检查实际发送的最终消息中有没有完整的新原块。

## 数据与复现

三道固定调优题包括资本开支、固定资产周转率和经营利润率变动原因。两道数值题分别回读 26、42 个最终入口以外的历史块，另核对 21 个原版实收块的来源，合计 89 次索引读取。叙述题不触发数值规则。实验先跑严格版，再用调优题诊断表名缩写和年份表头的格式，随后冻结“待核原表”规则。开发集只用来检验已冻结的规则。

严格版和原版都答对 1/3，正确且引用受支持的都是 1/3，错转对和对转错都是 0。三道题的最终请求逐题相同。第一批历史回读总耗时 2.28 秒，89 次均为索引读取，没有增加回答或审查模型调用。加入待核原表、要求保住原先所有完整块时，两组也都答对 1/3；其中正确且获裁判认定引用有支持的题，原版 1 题、回读版 0 题。两组实际收到的材料完全相同。资本开支题确实找回一块第 5 名的历史原文，但最终预算检查退回了原版。这两次实验均为 3 题 × 2 个方案，各 6 次真实回答、6 次独立评分。见[严格版结果](../reports/round7-history-strict.json)和[保护原有块的结果](../reports/round7-history-protect.json)。

开发集已有 39 道题，其中 38 题有可核对的单次回答快照，5 题能列出具体财务取数项。累计读取 177 次，核对 153 个最终入口之外的原块。只有速动比率题找到可补材料。一项经过严格核验，四项找到含对应行和年份的待核原表，共三块，仍有一项未补齐。不允许挤出旧材料时，全组没有新增送达。允许置换时，该题获得三个完整新块，原来实收的一块退出；其余可回放题无材料变化。资本开支调优题则增加一个完整新块，原来实收的两块退出。开发集这一步只做回放，随后选取唯一真正改变材料的开发题独立重答，没有按判分筛题。[开发集保护原块](../reports/round7-history-dev-replay.json) · [开发集允许置换](../reports/round7-history-dev-swap-replay.json)

服务器在项目虚拟环境中运行以下入口。`$SOURCE` 指已有原生回答快照目录，`$OUT` 指新的私有输出目录。运行者需要项目已有索引和专用模型服务。逐题原文、模型请求和答案仅存于私有目录。

```bash
# 严格核验并保护原有材料
python -m timeguard.paired_trial "$SOURCE" "$OUT" --arms original history_read
# 同一命令添加 --history-tables 可送入待核原表，再添加 --history-swap 可置换原有位置
# 对两组实际生成的回答分别评分后，导出脱敏统计
python -m timeguard.paired_report "$OUT" data/financebench/gold.jsonl "$REPORT" original history_read
# 只做离线回放，检查哪些题的材料会变
python -m timeguard.history_read "$SOURCE" "$REPORT" --history-tables --history-swap
python -m unittest discover -s tests -q
```

## 允许原表占用原有位置的真实结果

首次配对中，调优三题由 1/3 正确变成 2/3 正确，且正确题均有裁判认定的引用支持。资本开支一题错转对，无对转错。四个标准题页中，模型实收覆盖由 1/4 变成 2/4。原版和新版各使用 3 次回答及 3 次裁判，回答输入分别为 39,045 和 39,031 token，输出分别为 951 和 980 token。三题回答耗时加总分别为 79.33 秒和 79.18 秒，另计索引回读及裁判。用途是验证同样的证据预算内换进一张表会怎样。[首次三题结果](../reports/round7-history-swap.json)

独立的开发题询问跨年速动比率。首次配对两组都答错，引用支持均为未知。新版完整送达三个原块，包含一个程序可严格核验的取数项；新旧两组均未完整送达标注页的块。不能从这次结果推断其他 38 道开发题的准确率，也不能断定模型答错的唯一原因。两组各使用 1 次回答和 1 次裁判，回答输入由 13,001 变成 13,041 token、输出由 704 变成 824 token。[开发题首次配对](../reports/round7-history-dev-swap.json)

对真正改变材料的两题各再做一次固定条件的配对。资本开支复跑仍是原版错、回读版对且引用有支持。这是同一道调优题两次改善。完整表格可以帮助回答模型使用原文，即使严格读表程序无法独立确认其中的金额和币种。[资本开支重复配对](../reports/round7-history-capex-repeat.json)

速动比率复跑两组仍均判错、引用支持未知。[速动比率重复配对](../reports/round7-history-ratio-repeat.json)

本轮覆盖 4 道不重复的真实问答题。累计 24 次回答和 24 次裁判，均有结果，另外四个实验批次各有一次服务连通性探测。索引回读和离线分析不计入模型调用。服务器项目回归测试 175 项全部通过。现有结果支持按明确缺项回读历史原文，尚不足以把置换策略设为默认。下一步可在新的调优公司上固定一批查数题，重点检验替换材料带来的对转错。多期比率题还需要逐项确认每个操作数的期间、口径和来源。
