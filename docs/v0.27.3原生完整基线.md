# v0.27.3 原生能力基线

本轮用于确认固定版 RAGFlow 在现有英文财报任务上的原生能力，再为后续升级建立参照。源代码冻结为 TimeGuard-RAG 提交 `9c374a1`、RAGFlow 提交 `8090ffd8ba6098813d7f7ec2c4b8774f36c8423a`。服务器主工作树中的未提交改动不混入本轮；新增驱动位于独立工作树。R0 和 R1 结果均不覆盖。

“原生”指RAGFlow算法与工作流未改动，模型传输仍是`codex-app-server-structured-output-v1`，不能称为原生商业模型API的等价结果。该实验也不代表所有模型与所有参数组合的性能上限。

## 已有功能的边界

底座已有解析、模板分块、向量化、混合检索、文档元数据过滤、专门重排、关键词增强和 Agentic RAG。项目 R0 提供数据准备、公司分组、独立评测、调用审计及索引核验。当前已提交 R1 另有引用编号修正、实收提示块跟踪、公司与期间检索、披露日期过滤、表格行组和父表对照、重排长输入适配，以及 FastAPI、LangGraph、Decimal 计算和 SQLite 会话保存。它们不能算作未经修改的原生基线。

## 固定实验范围

使用同一84份财报索引、本地英文BGE、相同生成基础模型与low模型思考强度。普通、关键词、专门重排、公司字段半自动过滤、全自动元数据过滤、原生Agentic low/medium/high/ultra，以及组合配置共十组分别留存结果。Agentic档位控制应用层检索流程，与生成模型的六档reasoning_effort不同。

原生low只作直接搜索，不具有medium以上的工具循环。已有模型未登记工具能力时，原生入口会回退普通问答。本轮使用独立实例登记工具能力，观察实际RAG工具、检索、过滤和重排调用。提供商对象的工具标志在绑定时才变为真，不能把绑定前的假值误判为模型不支持。

原知识库的原生文档元数据为空。本轮先对84份文档完整备份，再从公开文档台账登记`tg_native_company`及`tg_native_report_year`，不用逐题金标。公司半自动组仅选择公司字段，避免把报告年份误当作数字所属年份；全自动组允许原生模型选择字段和条件，潜在报告年份误筛属于该组需要观察的行为。手工过滤38项验证32家公司、年份范围、与/或逻辑、缺失字段、空匹配及范围交集。实验后只在元数据仍等于本轮预期值时恢复，存在其他写入则停止，禁止覆盖他人更新。

专门重排采用已准备的固定CPU交叉编码器。未经适配的原生TEI提供商和显式分词器截断适配须分别标记；评分输入截断不改变返回的证据正文。原生Agentic可能不使用普通对话的重排模型字段，是否生效以检索调用轨迹为准。

组合组的精确定义为：公司字段半自动过滤、原生Agentic medium，并配置与重排组相同的重排字段；关键词增强关闭。它不是全部开关全开。单题烟测中实际发生17次检索、1次元数据过滤，重排实际调用为0；完整组继续按实际轨迹统计，不能只凭参数存在声称重排已参与。

本轮不修改原生提示词、知识块编号、Agentic预算或检索算法。观察钩子只记录参数、摘要和原样返回的结果。普通链路仍存在提示块一基编号与接口零基解析的已知差异，原生引用支持统计不能冒充提示块语义支持率，也不作为选优主要依据。

此处“完整”指该冻结财报问答任务的原生对照矩阵，不表示穷尽RAGFlow所有文件类型、外部联网工具或所有功能组合。知识编译、图谱、父子索引等需要新派生索引；多模态和真实逐token流式还受当前模型入口限制，不得仅开配置就声称已验证。

## 执行与评分规则

先做十组真实烟测。用户在观察到深档单题需21–38次模型调用后，明确选择“核心对照组跑满，深档只验证功能，优先形成可用基线”。最初将普通、关键词、专门重排、公司半自动过滤、全自动过滤和原生low收敛为六个完整核心组。

用户随后要求解释十组、39题与150题的关系，并审查可以省去的部分。审查期间先完成普通、关键词、专门重排、公司半自动过滤四个共同组。用户继而明确选择除Agentic medium/high/ultra三组外，其余配置完整运行，因此最终开发集范围为七组：普通、关键词、专门重排、公司半自动过滤、全自动过滤、原生low和组合。组合配置本身采用medium工具循环，仍单独跑满39题；不能将它与medium单独配置混为一组。三个深档单独配置只报告功能烟测，不据单题结果比较总体质量。原始计划和各次范围变更记录分别保留。

用户同时明确选择“先汇总七组39题，150题暂缓”。本轮主要答题量为`7×39=273`题次，复用已完成四组，仅补后三组，不启动新增111题；实际模型调用另含裁判、中间工具及重试。

39题是现有开发集；150题由88题调优集、39题开发集与23题保留测试组成。十组是不同能力的对照配置，39与150是题目数量，不是模型调用次数。生成之外还有独立裁判，关键词提取、过滤和Agentic循环还可能触发额外调用。若采用四组开发集再补齐所选配置，主要答题量为`4×39+111=267`题次；最初十组开发集加重跑150题为540题次，均不含烟测、重试和中间调用。

金标只在生成结束后进入独立medium裁判。每题隔离、双并发、首次生成失败后停止同组补题，收完在途请求；其他独立配置可继续验证。失败、未发题、未知判断及失败调用成本全部保留，不用新结果覆盖旧记录。

模型暂定选优仅在最终确认范围内的完整核心组之间，按固定开发集的判对数量优先、未知数量次之、平均耗时再次之，不称为全部Agentic档位中的最优配置。未知判断单列，已判定子集率与全量率分开报告，不把保守边界称为完整准确率。完整150题含开发题，后续全量结果不能称为新的独立泛化成绩。实际费用未知时保持空值。

每组记录计划分母、源码和配置摘要、实时索引快照、真实模型调用、token、耗时及原始错误。实验使用独立模型桥和审计文件，不与R1应用共享批次审计窗口。网络故障及恢复前后的运行分别留存。

本轮单题耗时覆盖一次原生问答内部的检索和生成，没有额外发出R0运行器中的诊断检索。独立工作进程启动成本另计批次墙钟，不能将本轮单题平均数与旧R0双检索总耗时直接计算加速比。若继续150题，严格校验所选配置的题目、源码、参数、索引及裁判输入后复用原39题，只新增111题与相应裁判；不读取已有答案构造新增请求，不丢弃原未知判断，来源成本累计保留。

若在元数据已恢复后继续带过滤的配置，必须先依据同一公开台账重新登记本轮字段并通过过滤检查，才能声称与原39题条件相同。仅核对文档数和分块索引快照，不足以证明文档元数据仍处于实验状态。本轮用户选择暂缓150题，不会执行这一步扩展。

网络中断恢复同样另建目录，只按请求状态复用成功行、补发失败或未发题。原始失败批次的39题计划、已完成数、失败数和未发数单独保留；不按答案对错决定重跑，也不覆盖旧结果。

专用桥、独立凭据与输出目录须先由受限的运行环境准备。上述命令不能通过现有R1私有凭据推断本轮桥令牌。运行轨迹、原始文档及凭据继续排除Git，仅提交工具、测试、文档和不含长原文的结果摘要。

完整组应显式指定`--arms`。驱动未指定该参数时默认遍历十组；上述示例对应用户选择的七组。当前运行由独立监督器限制，不会自动执行三个深档完整组或150题。

模型结果尚未人工复核。公司半自动组有1题未知，全自动组有2题未知，不能把剔除未知后的子集率称为39题完整准确率。按预先声明的规则，组合组暂选第一，20题判对、19题判错，不代表已证明优于所有参数组合或存在统计显著优势。全自动和关键词分别判对15、14题，可保留为低成本参照。

组合组实际发生318次检索和39次元数据过滤，普通对话重排器调用为0。回答阶段共600次模型请求（含2次失败），另有39次裁判；全自动组的回答阶段为78次、原生low为156次、普通组为39次。原生low此次与普通组同为10题判对。组合组多判对题目，但调用和耗时也明显增加；其平均耗时包含转发异常期间的等待，不能直接解释为纯算法推理速度。

重排39题均实际调用重排器，其中19题未召回片段；未经长输入适配的原生TEI路径另有HTTP413失败，不能把兼容组当作未适配路径的成功证明。

过滤离线诊断显示，全自动组在34题中选取比公司半自动更小的文档范围；38题保留至少一份金标证据文档，另1题未额外限制。此轮未发现全自动组排除全部金标证据文档的情况。文档被保留不等于正确片段已召回，也不等于答案正确；金标仅用于生成后的独立诊断，没有回传生成端。

重排原批次因专用模型网络故障，留下30题成功、2题请求失败、7题未发。新目录复用这30题，只补9题后裁判全部39题；原批次和失败成本均保留。最终报告同时列出中断批次和恢复组，不能用恢复组覆盖原失败记录。这里的平均单题时间使用成功回答行，原网络失败阶段另记，不用于推断算法加速。

续测时专用模型出口曾出现健康异常，自动重连后继续运行；异常期间新增2次失败模型请求，最终39题组合回答均成功，失败调用及未知用量保留。没有为此改变模型、提示词、检索参数或Agentic预算，也没有重跑已成功的题目。各成功行中的等待时间保留。

38项手工元数据过滤检查全部通过；原生HTTP两轮会话均成功，SSE协议通过，但当前模型桥未实现真实逐token实时流。84份文档的本轮临时元数据均已恢复，索引健康为green；恢复后同一84文档快照一致，主工作树原有四个改动文件的字节摘要未变。离线工具校验117项全部通过。

本轮独占桥共记录1,477次实际调用，1,464次成功、13次失败，已返回用量合计20,023,136 tokens，13次失败未返回用量，实际金额未知。这包含此前烟测、中间工具调用、裁判和失败，不能用题目数量直接代替，也不能把未返回用量的失败当作零成本。来源指纹保持一致。安全摘要见[原生基线审查结果](../reports/native-baseline-20261109.json)，原始答案、财报内容、运行轨迹和凭据不提交Git。

## 后续实验的优先次序

1. 保留组合组作为本轮效果参照，关键词和全自动过滤作为低成本参照。先人工核对关键差异题、未知题和失败类型，再以同一口径逐项复验已有R1引用校准、期间检索与表格处理，不把它们全部叠加后归因。
2. 单独诊断重排的19题空召回，核对分数尺度、阈值与长输入截断，再做固定候选池的重排对照。当前结果不能推出所有重排模型都无效。
3. 对组合组设计调用预算、充分性停止条件及按题分流实验，比较判对数量、未知数、实际请求、token和耗时。先验证能否保留收益并减少循环，再增加Agent数量。
4. 本轮39题已经用于选优，后续正式泛化验证需要保留独立问题或新公司、期间样本。当前150题扩展继续暂缓；它包含开发集，不能替代新的独立验证。
