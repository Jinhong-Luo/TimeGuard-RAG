# 同一批二十块，按排名和筛选 Agent 各选四块

起点为第七轮 `32afb194b232f3d163ab55b37968590d1e0ab8b1`。两组只改变选四块的方法。先将原题送到项目原生 RAGFlow 混合检索接口，限定公司和可用报告，固定已有索引、相似度门槛和向量权重，保存按原顺序返回的二十个不同块、正文及指纹。查一次后两组共享结果。按排名组直接截前四，筛选组用一次专用模型看全体二十块原文和来源，选出四个不同编号。编号无效或请求失败就记录并回退前四。

两组用同一个上游最终回答节点、模型、提示及 8,000 token 预算，重新回答和独立评分。节点只收到本组四块，去掉旧研究摘要、旧答案和其他轮次的证据，避免原版研究过程向某一组透露结果。这是单次搜索到回答的受控实验；完整 Agentic medium 会改写问题、进行多次搜索。本轮原题直搜资本开支时，其标准页未进入二十块。上轮出现第 5 名的是早先另一批搜索，两次的排序和候选不同。

## 固定调优三题

沿用原定的资本开支、固定资产周转率和经营利润率原因三题。三题候选共覆盖 1/4 个标准题页。筛选组三题都成功换了块，原版与筛选组各有 12/12 块完整送达，标准页送达由 0/4 变为 1/4。首次均判对 0/3，错转对 0，对转错 0。两道数值题的严格校验均未确认所需的 4 个操作数。标准页进入最终请求后，该题的答案仍被判错。没有人工裁判，此处不能断言具体错因。

筛选组多用 3 次模型请求，合计输入 48,170、输出 283 token，逐题耗时加总约 75.5 秒。两组分别使用 3 次最终回答、3 次裁判。逐题用量、失败、实收及引用见[首次配对结果](../reports/round8-four.json)。第一次采集时，接口采用了不同的报告名字段，首次启动止于筛选模型调用之前，原池保留；修正字段映射后使用相同指纹续跑。服务连通性探测单列，不计成筛选或回答请求。

## 开发集保护样本

调优三题按排名组均错，无法据此测试对转错。为检验这个问题，额外从旧版完整开发运行中，按题号升序取三个不同公司各一道旧版判对、引用获支持、可还原回答快照的题，固定为 00382、00464、00685。旧评分只用于事前选题，两个方案的搜索与回答不读取旧评分或金标。旧版多轮端到端答对与本轮前四块能答对分别统计。这三题单列，不作为未见公司泛化或全开发集准确率。

保护样本首次从 1/3 判对变为 2/3，00382 错转对，00464 保持正确、引用支持从否变为是，00685 均错。对转错为 0，按排名原先答对的分母为 1。两组各实收 12/12 块。三题的标准页均未进入任何一组的二十块，筛选组仍有两题被判定正确且引用有支持。筛选额外输入 44,314、输出 180 token，三次耗时合计约 77 秒。[保护样本首次配对](../reports/round8-four-protect.json)

首次两批共 6 道不同题，每组 6 次回答、6 次裁判。筛选额外 6 次请求，输入 92,484、输出 463 token。调优三题固定两组的实际请求后复跑，仍为 0/3 对 0/3；复跑未再请求筛选 Agent。[调优复跑](../reports/round8-four-repeat.json)

00382 的独立复跑仍是原版错、筛选版对且引用有支持。首次两批合计 1/6 → 2/6，一道错转对，零道对转错。按不同题计只救回一道。两批连同复跑共 20 次回答、20 次裁判、6 次筛选；四个正式问答批次各有一次连通性探测，另有首次接口字段不匹配批次的一次探测。第一轮回归 178 项通过。保留筛选为实验选项，下一轮仅为检验反馈作用而让各组使用相同的首次筛选。项目默认仍为原生多轮研究。[翻转题复跑](../reports/round8-four-protect-repeat.json)

## 复现

在项目已配置的服务器运行。SOURCE 为原生回答快照，OUT 为新的私有输出目录。运行完成才由评分模块读取金标。

```bash
python -m timeguard.four_blocks "$SOURCE" "$OUT"
python -m timeguard.four_blocks "$SOURCE" "$REPEAT" --frozen "$OUT" --repeat "$OUT"
python -m timeguard.four_protection "$OLD_DEV" "$PROTECTION_SOURCE"
python -m timeguard.four_blocks "$PROTECTION_SOURCE" "$PROTECTION_OUT"
python -m unittest discover -s tests -q
```
