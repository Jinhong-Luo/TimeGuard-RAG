# 在缺项反馈后按财报目录补搜

固定起点为 `224a76c4740dcec51f53ed6c7b91bbbb72c149e7`。入口为现有 `timeguard.full_feedback` 缺项反馈流程。`--outline` 启用目录补搜，`--adaptive` 让首次筛选、旧池复查和补搜后筛选都可自主选 1 到 12 块。两个开关可分别启用。证据预算沿用原生 8,000 token，最终以实际请求内完整出现的原块统计送达。

目录从本地核对 SHA-256 的 PDF 正文中识别 Item、Note 和财务报表标题，使用 PDF 物理页码划分范围。程序用反馈生成的检索词、标题词及常见科目与报表的对应关系选择至多四个章节范围，再从这些范围的原生索引块找页，最多返回二十个块。目录按需在本进程缓存。输入只包括允许报告、原文和缺项。无匹配章节、无候选或 PDF 工具不可用时沿用原生补搜；文档身份或指纹不符时停止该次补搜。扫描件及复杂的跨页标题可能无法识别。需要 Poppler 的 pdftotext。

## 固定三道调优题的真实配对

冻结之前同一题的二十块首搜结果、主模型缺项、旧池复查和补搜词。对照组沿用原生补搜选出的四块。实验组改变取候选的方法，再用原筛选提示挑四块。两个方案均用原生回答节点实际重答、由模型重新评分。对照侧复用以前的检索与筛选决策，其历史费用不计成本轮实际调用。

| 配置 | 判对 | 正确且引用有支持 | 实收完整块 | 实收标注题页 |
| --- | ---: | ---: | ---: | ---: |
| 原生补搜，固定四块 | 2/3 | 1/3 | 12/12 | 2/4 |
| 目录补搜，固定四块 | 0/3 | 0/3 | 12/12 | 2/4 |

按联合指标，救回 0、损失 1。按答案，救回 0、损失 2。三题实际走目录，分别返回 7、15、18 块。解析 4 份 PDF，冷缓存共读取 20 批原生索引，每题各有一次补搜后的筛选模型调用，合计输入 68,972、输出 576 token。两组各有 3 次回答和 3 次裁判。目录导航本身没有额外模型请求。保持原生补搜为默认。本轮是三道固定调优题，未验证完整开发集。仅看标注页数无法确定哪些业务事实丢失。

## 复现

在专用模型桥和原生服务配置好的独立工作区，使用新的输出目录执行。原 PDF、逐题材料和请求留在私有目录。`POOLS` 为保存 pools-private.json 的原首搜目录，`FROZEN` 为上轮同一批题的三组反馈目录。

```bash
python -m timeguard.outline_trial "$SOURCE" "$POOLS" "$FROZEN" "$OUT" outline
python -m timeguard.outline_trial "$SOURCE" "$POOLS" "$FROZEN" "$SECOND_OUT" adaptive
```

完整开发集如需从头启用某一开关，分别执行 `timeguard.full_feedback` 的 select、trial、grade、confirm，每个阶段使用相同开关和同一独立输出目录。小样本的 adaptive 对照只改变最终一次筛选的块数，首次筛选、缺项、补搜结果均冻结，便于归因。无效编号、引文无法定位等按原反馈流程回退；并非每个选中块都会完整进入最终请求。

## 自主选块的三题筛查

保持相同的原生补搜结果，只在补搜后最后一次筛选放开数量。资本开支、固定资产周转率、经营利润率原因三题依次选择 1、3、7 块，模型收到全部 11 块。固定四块组实收 12/12。两组各答对 2/3、判错 1/3，联合达标从 1/3 变为 2/3。周转率答案两组均对，自主选块组的引用通过；没有新增正确答案或原达标题退步。此次复用原搜索，执行三次新筛选、两组各三次回答和三次裁判。筛选共用 80,908 个输入及 531 个输出 token。小样本用于决定进入开发集配对。[三题机器报告](../reports/adaptive-supplement-tune.json)
